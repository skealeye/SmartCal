# SmartCal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows tray calendar popup that merges several Google calendars, sends meeting toasts, and has a Claude chat that edits the calendar.

**Architecture:** A PyQt6 tray app. A background sync thread pulls events from each Google account into a local SQLite cache. The popup reads only from the cache, so it opens instantly. The chat runs Claude tool use against a small calendar-actions layer that records an undo snapshot before each write.

**Tech Stack:** Python 3.14, PyQt6, google-api-python-client + google-auth-oauthlib, SQLite (stdlib), anthropic SDK, winrt/windows toast library, pytest.

**Spec:** `docs/superpowers/specs/2026-11-04-smartcal-design.md`

## Global Constraints

- Windows 11 only. US spelling in UI and docs.
- Popup visible within 200 ms of tray click (window prebuilt and hidden; reads cache only).
- Claude API key in `.env` (gitignored) with `.env.example` committed. Never commit secrets or OAuth token files.
- Default Claude model `claude-sonnet-5-5`, configurable. Chat context = today + next 7 days, all calendars; history is session-only.
- Meeting toast default lead time 10 minutes, configurable per calendar; calendars can be muted.
- Undo keeps the last 20 changes on disk. Delete asks first; ambiguous requests ask one question; unspecified calendar with 2+ active accounts asks.
- Chat reminders are local timers saved on disk, not calendar events.
- Directions link: `https://www.google.com/maps/dir/?api=1&destination=<url-encoded place>`; no origin, no extra API key.
- Week/Month window is read-only in v1.
- App version in `smartcal/__init__.py` (`__version__`), shown in the popup footer. Start at `0.1.0`; bump the patch version on every task commit and put it first in the commit subject, e.g. `v0.1.3: add sync`. Tick the task's checkboxes in the same commit.

## Review Focus

Failure modes the spec implies but does not spell out (each has a test in the named task):

1. Offline or expired/revoked Google token: popup still shows cached events, shows a small "offline" or "sign in again" note, never crashes (Task 3).
2. All-day and multi-day events: appear in today's agenda as "All day", never trigger a toast at midnight (Tasks 3, 6).
3. Recurring events edited or moved: "move this appointment" changes only that occurrence (Task 8).
4. Time zones and DST: work and personal accounts in different zones, events across a DST change, display in local time (Task 3).
5. Claude API missing key, error, or timeout: chat shows a clear message, tray and notifications keep working (Task 10).
